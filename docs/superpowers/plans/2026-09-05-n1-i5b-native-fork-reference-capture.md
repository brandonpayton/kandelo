This increment: (1) implement the **funcref** capture path in native Rust + thread a **real module-state arena**, so a funcref reconstructs across a native fork (the already-built replay then works); (2) **gate** externref/struct/array/i31/static-root capture to `EOPNOTSUPP` (parent-side clean abort, no child spawned), exactly as Node/browser do. This is native PARITY — the foundation for F5/F6 (which later re-instrument provenance to LIFT the gates on all hosts). Frames (I4) + replay (I5) unchanged.

**NOT this increment:** lifting any gate (that's F5 externref / F6 GC — they need re-instrumentation). Do NOT reconstruct externref/GC here; gate them, matching the platform contract.

**Architecture (grounded):** capture is NOT module-owned on any host — Node/browser do it in host JS (`ForkReferenceTransaction`), so native does it in host **Rust** (this is the current design; F5/F6 may move it into the module later, out of scope here). The ~15 capture-side guest imports have **no** fork-module exports, so this is native host bodies, NOT a module-export flip. For the SUPPORTED set (funcref), native implements 6 real bodies; for the GATED set, native implements a shared gate-stub that raises `EOPNOTSUPP` on the parent during capture (the fork aborts cleanly, no child). The real module-state arena replaces `write_empty_module_state_arena` so capture writes a funcref reference graph the replay (`fm_begin_reference_replay` at the two `drive_reference_replay` call sites) reconstructs.
